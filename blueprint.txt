Level-Compiler Search Blueprint
================================

Goal
----
Implement a combined feature/data search that makes the main app easier to approach.
This blueprint is intentionally limited to planning. It must not modify LC_modules.

Core Logic Constraint
---------------------
Do not modify:

- LC_modules/LevelCompilerCore.js
- LC_modules/LevelCompilerAge.js
- LC_modules/LevelCompilerPlot.js
- depth, age, correlation, calculation, import/export serialization logic in main.js

Search must stay in the UI/navigation layer:

- read existing renderer-side LCCore data
- trigger existing UI actions where possible
- avoid new model mutation paths

Recommended Direction
---------------------
Add an independent Search UI at the far right of the existing tool row in the main renderer.

The current main window already has:

- renderer/index.html
  - #toolbar
  - existing tool buttons
  - .rightsidemenu / .hole_menu / #hole_list
- renderer/index_styles.css
  - #toolbar button sizing and layout
  - .rightsidemenu and #hole_list styles

Place search as a separate block at the right end of #toolbar, not inside the right side menu.
Keep the existing #hole_list and right side menu unchanged.

Target Files
------------
1. renderer/index.html

Add a compact search block at the far right of #toolbar, after the existing tool buttons.

Suggested elements:

- #lc_search_panel
- #lc_search_input
- #lc_search_results
- #lc_search_empty

Keep #hole_list unchanged.

2. renderer/index_styles.css

Add styles for the search panel:

- #toolbar right-end placement
- independent layout block separated from icon tools
- white background
- thin #ccc border
- compact font size
- stable input width
- results dropdown positioned below the search input
- scrollable results
- simple selected/hover state

Do not introduce a visually heavy card layout. Match the existing practical toolbar style.
Use margin-left: auto or equivalent flex layout so search stays at the far right of the tool row.

3. renderer/js/renderer.js

Add all first-pass search behavior here.

Suggested functions:

- buildSearchIndex()
- normaliseSearchText(value)
- searchItems(query)
- renderSearchResults(results)
- runSearchItem(item)
- clearSearchResults()
- scrollToSearchItem(item)
- scrollToDepth(depthValue)

Rebuild the search index after loadModel() updates LCCore and the hole list.
Clear the search state when models are unloaded or LCCore is reset.

4. preload/preload.js

No change required for the first implementation if feature actions only use existing LCapi methods.

Only add new preload APIs if a later phase needs to open tools that currently have no main-renderer API.

5. main.js

Avoid changing this in the first implementation.

Only add small UI IPC wrappers in a later phase if search needs to open:

- Converter
- Labeler
- Plotter window
- About
- Check update

Do not touch core calculations, age/depth conversion, correlation logic, or serialization.

Data Index Design
-----------------
Build a plain array from renderer-side LCCore:

{
  type: "project" | "hole" | "section" | "marker" | "feature",
  label: string,
  subtitle: string,
  id: array | null,
  keywords: string,
  action: string
}

Suggested labels:

- Project: project.name
- Hole: hole.name
- Section: section.name
- Marker: marker.name

Suggested subtitles:

- Project: "Project"
- Hole: "Project / Hole"
- Section: "Project / Hole / Section"
- Marker: "Project / Hole / Section / Marker"

Search Matching
---------------
Use simple local matching first:

- lowercase
- trim
- collapse repeated whitespace
- split query by spaces
- require all terms to match somewhere in keywords

Scoring:

1. exact label match
2. label starts with query
3. keyword starts with query
4. keyword includes query
5. feature/data priority tie-breaker

Limit rendered results to about 30 items.

Data Navigation
---------------
Reuse the existing scroll math from the Finder move handler in renderer.js.

Initial version:

- Marker: scroll to marker[current depth scale]
- Section: scroll to midpoint of first and last marker where available
- Hole: scroll to first section top marker
- Project: scroll to first hole/section top marker

Vertical movement is enough for phase 1.
Horizontal movement can be added later using project/hole order calculations if needed.

UI Behavior
-----------
Search input placeholder:

Search data and tools...

Behavior:

- search input sits independently at the far right of the tool row
- search results open as a dropdown below the input
- input updates results immediately
- Enter runs the first result
- Escape clears query/results
- ArrowUp/ArrowDown move selected result
- clicking a result runs it

Empty states:

- no model loaded: show feature results only
- query has no match: show "No results"
- empty query: optional recent/common tools list
